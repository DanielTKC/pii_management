## Project Overview

This is a secure PII management system with three main services:
- **Rails API** (`rails-api/`) - RESTful API for PII management with SSN validation
- **Java Microservice** (`java-service/`) - SSN validation and AES-256 encryption service
- **React Frontend** (`react-frontend/`) - SPA for PII data entry and display

All services run in Docker containers orchestrated by docker-compose. See `doc/IMPLEMENTATION_PLAN.md` for the complete 13-phase development roadmap.

## Architecture

### Service Communication Flow
1. React frontend sends PII data to Rails API (`/api/v1/pii_records`)
2. Rails API validates SSN using its own SsnValidator service
3. Rails API calls Java service to encrypt SSN (HTTP POST to `http://java-service:8080/api/ssn/process`)
4. Java service validates SSN independently and encrypts with AES-256
5. Rails stores encrypted SSN in PostgreSQL
6. Display shows obfuscated SSN (`***-**-XXXX`)

**Key Design Principle:** Both Rails and Java maintain independent SSN validation logic - they do NOT call each other for validation, only for encryption.

### Database Architecture
- PostgreSQL 17 stores PII records with encrypted SSN
- Three main tables: `users`, `pii_records`, `audit_logs`
- Soft deletes via `deleted_at` timestamp
- Audit logging tracks all PII access (create, read, update, delete)
- SSN stored as `encrypted_ssn` (from Java service) + `ssn_last_four` (for display)

## Test-Driven Development (TDD) Workflow

**CRITICAL:** All coding MUST follow Red-Green-Refactor TDD:

1. **Write failing test** - Define expected behavior before implementation
2. **Run test** - Confirm it fails for the right reason
3. **Commit failing test** - Message: "Add tests for [feature]"
4. **Write minimal code** - Make test pass, don't modify test
5. **Run tests** - Ensure all pass
6. **Run linting** - `bundle exec rubocop` (Rails) or `mvn test` (Java)
7. **Commit implementation** - Message: "Implement [feature] - [implementation choice]"

### Test Tools
- **Rails:** RSpec + FactoryBot + SimpleCov (>90% coverage target)
- **Java:** JUnit 5 + Mockito + JaCoCo (>90% coverage target)
- **React:** Jest + React Testing Library (3-4 meaningful tests minimum)

Use FactoryBot for Rails test data, NOT fixtures.

## SSN Validation Rules (Implement in BOTH Rails and Java)

Both services must independently validate:
- Format: `XXX-XX-XXXX` (9 digits with dashes)
- Area number (first 3): NOT `000`, NOT `666`, MAY be `900-999`
- Group number (middle 2): NOT `00`
- Serial number (last 4): NOT `0000`
- Known invalid SSNs: `078-05-1120` (test SSN)

## Key Implementation Details

### Rails API (`rails-api/`)
- API versioning: All endpoints under `/api/v1/`
- Authentication: Protect all PII endpoints with `before_action :authenticate_user!`
- Java client: 5-second timeout, 3 retries with exponential backoff
- Pagination: Use Kaminari or Pagy, support `?show_all=true` parameter
- Audit logging: After-action callback logs all PII reads
- Soft deletes: Query scope `PiiRecord.active` excludes `deleted_at`
- Log filtering: Add `:ssn` to `config.filter_parameters`

### Java Service (`java-service/`)
- Encryption: AES-256-GCM with random IV per encryption
- Key management: Load from `ENCRYPTION_KEY` environment variable (Base64-encoded 32 bytes)
- Generate key: `openssl rand -base64 32`
- Key rotation: Document strategy (30 days or 64GB encrypted data)
- Endpoints: `/api/ssn/validate`, `/api/ssn/encrypt`, `/api/ssn/decrypt`, `/api/ssn/process`
- Health check: Spring Boot Actuator at `/actuator/health`

### React Frontend (`react-frontend/`)
- Routing: React Router with protected routes via `<PrivateRoute>`
- Routes: `/login`, `/`, `/pii/new`, `/pii/:id/edit`
- Auth: Store JWT in localStorage/sessionStorage, include in all API calls
- SSN masking: Input field auto-formats to `XXX-XX-XXXX`
- Middle name override: Checkbox sets value to `"N/A"`
- Pagination: Controls for page navigation + "Show All" toggle
- Confirmation: Modal confirmation required for delete operations

## Security Requirements

- **Never log SSN** - Ensure `ssn` in `config.filter_parameters`
- **No SSN in errors** - Sanitize all error messages
- **Audit all access** - Create `AuditLog` for create/read/update/delete
- **Obfuscate display** - Always show `***-**-XXXX`, never full SSN
- **Validate uniqueness** - Prevent duplicate encrypted SSNs in database
- **Rate limiting** - Use Rack::Attack for API endpoints
- **CORS** - Configure specific origins, not `*`

## Common Patterns

### FactoryBot Usage (Rails)
```ruby
# In spec/factories/
FactoryBot.define do
  factory :user do
    email { "user@example.com" }
    password { "password123" }
  end

  factory :pii_record do
    association :user
    first_name { "John" }
    last_name { "Doe" }
    ssn { "123-45-6789" }  # Will be encrypted via callback
  end
end

# In tests
user = create(:user)
record = create(:pii_record, user: user)
```

### WebMock for Java Service (Rails tests)
```ruby
stub_request(:post, "#{ENV['JAVA_SERVICE_URL']}/api/ssn/process")
  .with(body: hash_including(ssn: "123-45-6789"))
  .to_return(
    status: 200,
    body: { valid: true, encryptedSsn: "...", lastFour: "6789" }.to_json,
    headers: { 'Content-Type' => 'application/json' }
  )
```

### Audit Log Pattern (Rails)
```ruby
# In PiiRecord model
after_create :log_create
after_update :log_update
after_destroy :log_delete

def log_create
  AuditLog.create(
    auditable: self,
    user: user,
    action: 'create',
    ip_address: Current.ip_address
  )
end
```
